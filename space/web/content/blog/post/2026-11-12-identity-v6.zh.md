> 本文是「styrigx 鉴权体系规范的变迁」系列的一篇，接在[《账号与进站 V3》](/blog/zh/post/2026-11-09-account-v3-site-entry/)之后。V3 的「两套票」在这一版合成了一套。

V3 把「能不能进来」和「能不能写」拆成两套票，确实理顺了一阵。但用下来，两套票各自带着会话、恢复钥匙和再验证，叠在一起又长出了新的重叠：进站有一把恢复钥匙，账号也有一把；`sudo root` 要 reauth，`sudo -v` 又是另一种再验证。v6 要解决的就是这件事：**站上只有一个签发者，只有一套身份。**

## 一、网关的角色变了

V3 里网关既签发进站会话、又判定请求能不能过。v6 之后，网关只做后一件事：

- **签发**：`@` 前面的所有身份，都由账号服务签发和管理。可以类比 Linux 的 PAM 加 `/etc/passwd`：谁是谁、凭据对不对、属于哪些组，只有这一处说了算。
- **判定**：网关收到请求，只拿会话去问账号服务「这是谁、在哪些组」，再按路由表决定放不放，不签任何东西。

会话本身也简化了。客户端只拿到一个不透明的随机 id，放在 HttpOnly、Secure、SameSite 的 cookie 里；uid、组和身份栈都存在服务端，客户端 token 里什么都不带。既然会话不再是签名令牌，站内原来那两对签名钥匙也就没有存在的理由，一并删除。

## 二、理念：金字塔，不是平级协作

设计时最容易犯的错是照抄。Linux 是多用户平级协作的系统：很多人共用一台机器、各有各的家目录，`owner / group / other` 是用来调解这些平级用户的。

这个站不是这样。它是一个人的空间，**自上而下、纵深一体，是一座金字塔**，权限只会由高向低授予。所以 v6 借了 Linux 的词汇（root、su、sudo、组、身份栈），但没有借它的平级协作模型：这里没有平级，也就不需要 other。

主机名固定是 `space`，提示符就是 `<用户>@space:<路径>`。金字塔从上到下是：

| 层 | 是谁 | 能做什么 |
|---|---|---|
| root | 唯一的超级用户，uid 0 | 什么都能做；日常只管用户、凭据、授权和批量 / 结构删除 |
| 站长 | styrigx，uid 1000，第一个普通用户 | 站上内容的主人；名片、头像、偏好都归他；后台操作用 sudo |
| 普通用户 | uid 1001 起，由 root 建 | 只读：听歌、AI、状态卡，以及公开内容 |
| 访客 | 没登录，`nobody@space` | 公开内容 |

日常状态是 `styrigx@space`。只有真要动后台时才 `sudo` 一条，或者 `su root`。

root 与站长的凭据完全独立：密码、通行密钥各自注册，通行密钥的显示名也分开写 styrigx 和 root，在手机的密钥管理里一眼能区分。

## 三、权限就是组

权限模型是附加组式的，没有上 rwx。

**路由表是唯一的权限来源。** 每条接口都写明一个档：`public`、`user`、某个组名、站长或 root。没写进表的，一律拒绝。请求方法和权限无关：导出是 GET，但归 root；向 AI 提问是 POST，但那是「用」，不是「写」。

**判断只在一处。** 顺序固定为三步：

1. 救援会话只认白名单命令需要的接口，其余一律拒，不往下走；
2. root 一律放行，不留例外；
3. 其余按路由档：public 谁都行，user 是任一已登录身份，组名看在不在组里，站长就是 styrigx 本人。

「救援先于 root」这一步只实现一次，所有入口共用，不各写一份。否则迟早会有一条路忘了先拦救援。

组有这些：

- `wheel`：可以 `su root`；`sudoers`：可以 `sudo`。
- `listen`、`ai`、`status`：听歌、AI 窗口、状态卡。
- `curio-write`、`daymark-write`：奇趣、日刻的上传、编辑和单条删除。

站长默认在全部这些组里。普通用户只给只读的 `listen`、`ai`、`status`，代码直接拒绝把他们加进 `wheel`、`sudoers` 或写组。新用户默认没有组，fail-closed。批量和结构性删除（整个收藏夹、整个应用、用户、清空）不属于任何组，只属于 root。

**权限层级就是 `man` 的顺序。** `man` 的命令索引按 root → 站长 → 普通用户 → 访客分段，每个人只看到自己这一层及以下的命令。一个命令不在你的 `man` 里，对你来说它就不存在：输入它得到的是「找不到命令」，而不是「权限不够」。这让权限边界和你能看见的东西完全一致。

## 四、su 压栈，sudo 借一条

身份切换只有两种动作，分工很清楚：

- **`su <用户>`**：输目标用户的凭据，切换过去，**压栈**。访客可以 `su` 成站长或普通用户；`su root` 只有 `wheel` 组的人能用，输的是 root 的凭据。普通用户之间不能互相 `su`，要换人先 `exit` 回访客。
- **`sudo <命令>`**：`sudoers` 里的人每次输**自己**的凭据，借 root 执行这一条，不发票据，不压栈。

`exit` 弹一层（root → 站长 → 访客），`lock` 清空整个栈并删掉服务端的会话。`who` 显示完整的栈路径，比如 `root via styrigx`。栈最多三层，存在服务端。

root 的公开登录在代码层面是禁止的：访客发起的登录绝不会签出 uid 0，公开登录接口直接拒收 root 的凭据。想成为 root，只能先成为站长，再 `su root`。

进站也不再跳页。以前未登录访问会把你带去锁屏，验证完再跳回原页；现在就在原地 `su`，原页面不动。

### 会话时长

| 层 | 时长 |
|---|---|
| 站长 | 30 天滑动续期；剩余不足一半才续，每个会话每天最多写一次 |
| root | 最长 1 小时；前台空闲 15 分钟就弹回站长，页面隐藏或锁屏时暂停计时 |
| 救援 | 15 分钟，不续期 |

站长层的续期做了节流：判定请求时只读不写，避免每个请求都写一次数据库。

## 五、sudo 夺不走 root

站长在 `sudoers` 里，意味着拿到站长凭据的人可以经 `sudo` 做 root 能做的几乎一切破坏。这是金字塔模型必须正视的一点：**真正的边界是站长凭据，要和 root 同样严防。**

但有一件事 `sudo` 做不到：动 root 自己的凭据。`sudo passwd root`、用 sudo 给 root 增删通行密钥，一律拒绝；改 root 凭据要求当前栈顶就是 root（`su root` 或救援会话）。

这样即使站长凭据被盗，攻击者能借 sudo 搞破坏，却夺不走 root。我用 root 重置站长凭据就能收回，连救援钥匙都不用动。代价只是一条检查和一条测试。

几条相关的护栏：

- 不能删 root，也不能删站长（否则名片没有主人）；
- 从 `wheel` 或 `sudoers` 移走最后一个成员时会警告：移完之后只能靠救援钥匙上 root。

## 六、用户管理

普通用户由 root 管，命令照 Linux：

- `useradd <名> [-e 日期] [-G 组]`：生成 16 位以上的随机一次性密码，只显示一次，库里只存哈希；首次登录强制改密码，一次性密码 24 小时内有效。`-e` 按 Linux 语义：那天 00:00（上海时间）起失效。
- `userdel <名>`：清掉会话、凭据和组，用户行不删，改名为墓碑并禁用；uid 永不复用，免得新用户继承旧 uid 下的数据。名字可以再用。
- `usermod -aG / -rG`：加组、减组。
- `passwd <名>`：重发一次性密码，对方所有会话作废。
- 到期：自动禁用并作废会话，30 天宽限期后按 `userdel` 的方式删除。

站长用 `passwd`、`passkey` 管自己的凭据；普通用户只能 `passwd` 改自己的密码，不能管通行密钥。改自己的密码要先输当前密码，通行密钥自带 WebAuthn 验证。

这也取代了 V3 的分享短链。以前要给别人看点东西，是发一条带期限的短链；现在是 root 建一个带期限的普通用户。短链整套删掉了，代理订阅的 `/s/<令牌>/<来源名>` 保留。

## 七、恢复钥匙只剩一把

V3 有两把恢复钥匙，v6 只剩一把，而且只管 root。普通用户忘了密码，由 root 重置。

钥匙放在 Cloudflare Secrets Store，Worker 运行时只有读取权限，代码里不出现任何写或删的调用，合并前做静态检查。值由我在后台设定、更换，改完即时生效，不用重新部署。

救援流程类比单用户模式：

1. 访客输入 `rescue`，再输恢复钥匙；
2. Worker 做常量时间比对，通过就签一个 15 分钟的一次性 root 会话，不续期；
3. 救援会话只认白名单：`passwd`、`passkey`、`whoami`、`groups`、`exit`、`lock`，连换钥匙都不在里面；
4. 成功后提示我去后台换新值。

每次救援成功，会在数据库记下这把钥匙的哈希指纹（不存明文），永久保留；同一个值再用就直接拒绝。指纹写不进去，就拒绝救援，fail-closed。全丢了怎么办？能登 Cloudflare 就设个新值。不做破窗。

## 八、看得见的部分

身份统一不只是后台的事，界面上也要能一眼看出「我现在是谁」。

**头像就是 whoami。** 全站只有一份配置（头像、偏好、名片），归站长，root 作为超级用户共同持有。所有人看到的都是站长设的头像，但角标不同：root 在右下角带 `#`，站长带 `$`，和终端提示符的结尾一致；普通用户和访客不带角标。站长和 root 点头像打开账号页，普通用户的头像只是装饰，不可点。

**盾牌是身份徽章。** 顶栏的盾标分四档，盾越实，身份越高：访客空盾，普通用户盾里一个小人，站长打勾，root 实心盾并保留那个勾。站长和 root 用主题色，访客和普通用户用灰色。点盾牌不会直接切换，只在终端里预填下一步命令，回车才生效：能往上走就预填晋升（访客 `su `，站长 `su root`），已经到顶就预填 `exit`。

**提示符跟着身份走。** 终端、AI 窗口提问行、全站装饰提示符都按当前身份显示：访客 `nobody@space:~$`，站长 `styrigx@space:~$`，普通用户 `<名>@space:~$`，root 用 `#`。

**账号页只剩三样。** 个人信息卡、设备卡、一个 `lock` 按钮。没有账号安全卡：密码和通行密钥只在终端里用 `passwd`、`passkey` 管。账号页上的后台改动（比如踢设备）点下去只在终端预填命令：站长预填 `sudo …`，root 不带 sudo，输入和验证都在终端里完成。

奇趣和日刻的导入页也简化了：原来的「去验证」按钮删掉，导入按钮本身就是触发，服务端凭会话判断；没登录就打开顶栏终端、预填 `su `。

## 九、安全细节

- **防枚举**：用户不存在和凭据错误返回同一个错误，走同一条耗时路径；不提示某个用户有哪些验证方式。
- **限流两维**：按 IP 硬上限每分钟 6 次；按账号渐进退避，每个账号一个桶，首次失败后等 1 秒，再到 5 秒、30 秒、5 分钟，不硬锁。救援所有尝试共用 root 的那个桶。通行密钥不计入冷却。判定请求只读不写，认证失败才写计数。
- **哈希**：加盐加 pepper 的快速哈希，不用 bcrypt / argon2。Cloudflare Worker 每个请求只有 10 ms CPU，慢哈希跑不起；在线猜密码靠限流挡。全站只留一把 pepper。
- **epoch**：凭据、组、期限有任何变化都会递增，严格比对。自己改密码时当前会话续命；root 替别人重置，对方所有会话作废。
- **fail-closed**：没登录访问未写进路由表的接口一律 401；网关不再向下游写身份头，子应用一律凭会话自己判定。
- **审计**：useradd / userdel / usermod / passwd、su、sudo、救援、登录失败都记下 uid、命令、时间和 IP 前缀，保留 90 天；root 的特权内容操作也留痕。
- **一次查询**：判定一个请求只查一次数据库，会话、用户、组、epoch 一个 JOIN 拿齐。

## 十、怎么割接的

没有做新旧格式互转，而是分段割接，新旧并存跑，救援跑通再删旧：

1. **P1**：建表、组模型与唯一的判定函数、盘点全部路由（77 条，另有 11 条只走服务绑定）。
2. **P2**：su、sudo、exit、lock、用户管理命令、身份栈、前台空闲计时、头像跟身份走。
3. **P3**：救援入口 `rescue` 上线，端到端跑通。
4. **P4**：删旧。分享短链、旧进站签发、旧再验证、两把旧恢复钥匙、两对签名钥匙、应用授权、数字健康整套，连同旧表和旧数据一起删干净，不留兼容层。

每一段单独一个 PR，CI 全绿才合；删 secret 之前先确认部署变绿，删之后，回滚下限就是那次部署。

## 结语

V3 解决的是「一张票干两件事」，v6 解决的是「两套票叠在一起」。现在站上只有一个签发者、一套身份、一把恢复钥匙，权限从上往下流，你在 `man` 里看到什么，就能做什么。

网关还在，只是从「发票的」变成了「验票的」。这个系列也不会停在这里。
