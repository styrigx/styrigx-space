> 本文是「styrigx 鉴权体系规范的变迁」系列的一篇，接在《网站不再公开》之后。依据是 11 月 3 日的目标方案和对应的 PR 任务表。

上一版理顺了名字和票，但两个问题还在：账号鉴权的代码住在网关里，账号数据和锁屏数据挤在同一个 Worker、同一个库里；下游（子站接口、搜索、聊天）判断能不能写，看的还是网关那边的角色。这一版的总目标只有一句话：**门归网站，账号管授权，root 借鉴 Linux。**

## 一、账号拆出去（10-30 → 10-31）

账号鉴权整个搬进独立的账号 Worker：

- 账号 Worker 没有公开路由，浏览器只能走到网关；
- 网关验完门，通过服务绑定把账号路径转给账号 Worker；外面带进来的内部头先剥掉，免得有人伪造；
- 网关只通过一个专门的接口问账号会话的结论，网关里的账号代码、绑定、钥匙全部删掉；
- 账号数据搬出网关的库，迁移脚本带 dry-run、校验、回退和清理四步，中间一次原子切流。

层与层之间的边界也写进了检查：哪个 Worker 能调哪个、不能碰哪个，CI 里有规则管着。

## 二、进门二值（11-04）

拆完以后，锁屏这边可以大幅简化。原则一条：**进门只有「有」和「没有」**。

- 锁屏会话不再分访客和站长，有效就算进门；
- 会话里的角色字段、角色头、「仅站长」这类判断全部删掉；
- 记录会话怎么来的那个字段（密码、通行密钥、临时钥匙）只做审计，不做任何放行或拦截的依据。角色退役了，就不许拿它当新角色用；
- 锁屏侧原来叫 root 的根凭证改名 space：它是网站进站的根凭证，root 这个词留给账号；
- 临时钥匙和分享短链的新建、作废要先复验锁屏凭证。

进门是看的前提，不是授权。进了门，能看；能不能写，是另一个问题。

## 三、授权归账号（11-04）

能不能写、能不能动后端数据，一律由账号回答：

- 账号侧有一张作用域表：奇趣写入、日刻写入、偏好同步、头像写入等；
- 网关把账号给出的结论转交下游，子站接口、搜索、聊天都只认这个结论；
- 依赖方向反转：以前是账号看锁屏会话，现在是网关问账号要结论，Worker 只信网关转来的结论；
- 锁屏和账号互不打通：立即锁屏、锁定所有设备只清进门会话，不碰账号会话；账号退出也不碰锁屏。

搜索分两档：检测到账号会话就能搜包括私密内容在内的全部页面，没有就只搜公开内容。登录不是门槛，检测到才扩展。

## 四、root 借鉴 Linux

这一版第一次明确：root 是账号和用户的概念，借鉴 Linux 的超级用户；锁屏不是账号也不是用户，不需要 root。应用按作用域最小授权，敏感操作像 sudo 那样复验，各侧复用各自的复验短票。

这句话当时只是方向，真正把 root、用户、组做成一套，要等到 v6。

## 五、两套票

到这一版，站上实际上是两套互不嵌套的票：

| | 进站（网站的门） | 账号（授权） |
|---|---|---|
| 回答的问题 | 能不能进来看 | 能不能写、能不能看私密 |
| 凭证 | 锁屏密码 / 通行密钥、临时钥匙 | 账号密码 / 通行密钥 |
| 谁签 | 网关 | 账号 Worker |

这个划分后来被我叫作 V3 原则，几天后的《账号与进站 V3》就是把它定稿上线的那一版。
