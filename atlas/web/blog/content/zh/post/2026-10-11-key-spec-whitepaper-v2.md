> 本文是「Styrigx UI 鉴权规范」系列第二版，前一版见[《Styrigx 密钥规范白皮书 v1.0》](/post/2026-10-11-key-spec-whitepaper/)。

## 0. 摘要

Styrigx 由一个主站（styrigx.com）和若干子站（blog、book，以及以后的 music 等应用）组成，共用 `.styrigx.com` 下的登录状态。本规范定义这套站点群里所有签名密钥和通行密钥的命名、用途、存放位置、签发与验证方，以及从访客进入到子站敏感操作的完整鉴权流程。

v1.0 用三对 Ed25519 密钥隔离了三种凭证，但子站敏感操作要先做一次主站二次验证，再换取子站通行证，两层嵌套：主站密钥既管安全设置，又卡在 APP 通行证的签发链路上，一处配置缺失就会让两件不相干的事一起失败。v2.0 把模型重新划成**三个互不嵌套的信任域**：

| 信任域 | 密钥 | 类比 | 管什么 |
|---|---|---|---|
| 锁屏域 LOCK | `SGX_LOCK_*` | 手机的指纹解锁 | 三站解锁状态 |
| 应用域 APP | `SGX_APP_*` | 普通网站各自的登录 | 子站里的具体操作（book 上传、删除、换封面） |
| 主站域 STEPUP | `SGX_STEPUP_*` | 系统设置里的「验证身份后才能改」 | 只管主站安全与隐私的核心设置 |

v2.1 在 v2.0 的三域之上，把「谁能管钥匙」也分了层。核心原则八条：

1. **一种用途一对密钥**，绝不跨用途复用。
2. **只有主站签发**，子站永远只持公钥；主站密钥的公私钥都只在主站。
3. **三个信任域互不嵌套**：APP 验证不依赖主站密钥，主站密钥不参与任何子站凭证的签发。
4. **三层凭证，各管各的**：
   - **根凭证**（恢复用）：最后的恢复手段，平时不用；
   - **站长凭证**（owner 通行密钥 / owner 密码）：管「管理凭证」入口的二次验证；
   - **锁屏凭证**（lock 通行密钥 / 锁屏密码）：只管解锁。
   一旦配置了本层凭证，根凭证对该层自动失效——这叫「接管」。
5. **通行密钥三分类**：站长类（`owner`）、锁屏类（`lock`）、应用类（`app`）各自注册、各自验证，服务端双向拒绝混用。
6. **缺配置即拒绝**（fail closed），任何缺失都不会变成放行。
7. **所有凭证可过期、可撤销**：会话纪元一键作废全部凭证，应用纪元单独作废某个应用的凭证。
8. **恢复通道就是攻击通道**：任何站内恢复都要两把凭证（根凭证加站长凭证，缺一不可）；最后一道站外恢复独立于站内，由托管平台账号临时开启并自动过期，只讲原则——平台账号不安全则一切无意义。

## 1. 适用范围与角色

| 角色 | 说明 |
|---|---|
| 主站（space） | 唯一的签发方，持有全部私钥、主站公钥和根凭证；负责解锁、二次验证、APP 验证、通行密钥管理、根凭证恢复和锁屏重置 |
| 子站（blog、book 等） | 只验证，不签发；只持自己需要的公钥 |
| 所有者（owner） | 唯一能管理安全设置和执行敏感操作的人 |
| 访客（visitor） | 通过人机验证进入，可以浏览公开内容和部分只读页面，任何敏感操作一律拒绝 |
| CI | 每次运行临时生成测试密钥，只写入预览和测试环境 |

## 2. 威胁模型

本规范要防的是：

- **凭证伪造**：没有私钥的人构造出能通过验证的 cookie。
- **凭证越权**：低权限凭证被拿去做高权限的事，例如访客会话改设置、解锁会话直接上传、book 的通行证拿到 music 用。
- **通行密钥混用**：解锁用的通行密钥被拿去批准子站操作，或反过来。
- **凭证长期有效**：设备丢失、cookie 泄露或通行密钥被删除后，旧凭证仍能使用。
- **子站失守连带主站**：某个子站的配置或代码泄露，导致攻击者能签发凭证。
- **配置缺失导致放行**：部署时漏配变量，或平台额度耗尽时绕过函数直接出静态页。
- **跳转循环与开放跳转**：鉴权跳转在站点间来回弹，或 `return` 参数被利用跳到外部站点。
- **暴力破解**：反复尝试密码。

不在本规范范围内：Cloudflare 账号本身被接管、所有者设备被完全控制、浏览器零日漏洞、截图。

## 3. 命名规则

```
SGX_<用途>_PRIVATE   私钥（PKCS8 PEM）
SGX_<用途>_PUBLIC    公钥（SPKI PEM）
```

本地文件名对应为 `<用途>.key` 和 `<用途>.pub`。变量名只表达用途，不表达算法，算法统一为 Ed25519。

三类固定中文名：**锁屏密钥、APP 密钥、主站密钥**。「二次验证」只作为动作的名字（「做一次二次验证」），不再用来指密钥。

根凭证不是签名密钥对，而是只存在主站 Secret 里（`SGX_ROOT_KEY`）的一段恢复口令，界面统一称「根凭证」。

## 4. 三对签名密钥

| 中文名 | 变量 | 签发的凭证 | 有效期 | 私钥在 | 公钥在 | 管什么 |
|---|---|---|---|---|---|---|
| 锁屏密钥 | `SGX_LOCK_PRIVATE` / `SGX_LOCK_PUBLIC` | `sgx-verified` | owner 12 小时，visitor 1 小时 | 主站 | 主站、全部子站 | 三站解锁状态 |
| APP 密钥 | `SGX_APP_PRIVATE` / `SGX_APP_PUBLIC` | `sgx-app` | 10 分钟 | 主站 | 需要的子站（目前只有 book） | 子站敏感操作 |
| 主站密钥 | `SGX_STEPUP_PRIVATE` / `SGX_STEPUP_PUBLIC` | `sgx-stepup` | 10 分钟 | 主站 | 主站 | 主站安全与隐私核心设置 |

### 4.1 为什么是三对，而且互不嵌套

- **泄露隔离**：任何一对出问题，只影响它自己的用途，轮换也只动它自己。
- **密码学防越权**：三种凭证用不同私钥签名，一张 `sgx-verified` 不可能通过 `sgx-app` 或 `sgx-stepup` 的验证，不依赖代码里的类型判断是否写对。
- **故障隔离**：v1.0 里 APP 通行证要先拿到 `sgx-stepup`，主站密钥漏配会连带子站上传一起失败。v2.0 拆开后，主站密钥只影响安全设置，子站操作照常。
- **最小暴露**：主站公钥只在主站，子站根本不知道它；APP 公钥只发给真正需要的子站。

### 4.2 凭证格式

所有凭证都是点分字符串，最后一段是对前面全部内容的 Ed25519 签名（base64url）：

```
sgx-verified = role.epoch.exp.sig
sgx-stepup   = by.scope.epoch.iat.exp.sig
sgx-app      = owner.epoch.appEpoch.iat.exp.aud.scope.sig
```

| 字段 | 含义 |
|---|---|
| `role` | `owner` 或 `visitor`；`sgx-stepup` 和 `sgx-app` 只签给 owner |
| `by` | `sgx-stepup` 的签发依据：`root`（根凭证）或 `owner`（站长凭证） |
| `scope` | `sgx-stepup` 的用途：`root`（站长凭证管理）、`keys`（管理凭证）、`lockreset`（重置锁屏） |
| `epoch` | 会话纪元，见第 8 节 |
| `appEpoch` | 该 `aud` 的应用纪元，见第 8 节 |
| `iat` / `exp` | 签发时间和到期时间（毫秒） |
| `aud` / `scope` | 通行证给哪个子站、做哪类事，由主站白名单限定，例如 `book` / `upload` |

`sgx-verified` 的四段式格式是跨站契约：主站改格式时，所有子站必须在同一批变更里同步，三个仓库各有一条契约测试守住它，否则子站会因为解析失败把有效会话当成无效，陷入跳转循环。

### 4.3 cookie 属性

| cookie | 属性 |
|---|---|
| `sgx-verified` | `Domain=.styrigx.com; Path=/; HttpOnly; Secure; SameSite=Lax` |
| `sgx-app` | `Domain=.styrigx.com; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=600` |
| `sgx-stepup` | `Domain=.styrigx.com; Path=/; HttpOnly; Secure; SameSite=Strict` |

`sgx-app` 用 `Lax` 而不是 `Strict`，因为它要随「主站验证完成 → 跳回子站」这次顶层跳转送达子站；防伪造靠签名、aud 和极短有效期，而不是 SameSite。`sgx-stepup` 只在主站内部使用，用 `Strict`。

## 5. 通行密钥分类

签名密钥管「凭证由谁签」，通行密钥（passkey，WebAuthn）管「谁来批准签发」。v2.1 把通行密钥分成三类：

| 类别 | `class` | 用来 | 能换到什么 |
|---|---|---|---|
| 站长类 | `owner` | 「管理凭证」入口的二次验证 | `sgx-stepup`（`scope=keys`） |
| 锁屏类 | `lock` | 解锁三站 | `sgx-verified`（owner） |
| 应用类 | `app` | 批准某一个子站的敏感操作，每个应用一把 | 该应用的 `sgx-app` |

### 5.1 必须遵守的规则

- 每条凭据**必须**在服务端记录 `class`；应用类还**必须**记录 `aud`。
- 各类认证的 challenge **必须**只列出对应 `class` 的凭据，验证时服务端**必须**再次检查分类。理由：浏览器的凭据选择器不是安全边界，只靠前端过滤，换个请求就能绕过。
- APP 认证的 challenge **必须**只列出 `class=app` 且 `aud` 等于请求 `aud` 的凭据，服务端同样复核。book 的钥匙不能开 music。
- 认证时**必须**要求用户验证（UV，生物识别或 PIN）；challenge 按用途隔离、单次使用、5 分钟过期。
- **禁止**用密码换取 `sgx-stepup` 或 `sgx-app`，密码只能解锁。根凭证可以换取特定 `scope` 的 `sgx-stepup`（见 6.8），但**禁止**换取 `sgx-app`。
- **禁止**用锁屏类通行密钥签发 `sgx-stepup`（锁屏钥匙只管开门，不管改设置）。

### 5.2 注册时的固定名称

密码管理器（例如 Samsung Pass）保存通行密钥时，会显示注册时写入的用户名和显示名，事后修改很麻烦。因此注册参数在代码里写死，用户注册时不填写任何东西：

| 字段 | 站长类 | 锁屏类 | 应用类 |
|---|---|---|---|
| `rp.id` | `styrigx.com` | `styrigx.com` | `styrigx.com` |
| `user.displayName` | `Sloan Gray` | `Sloan Gray` | `Sloan Gray` |
| `user.name` | `ownerkey` | `lockkey` | 应用的 `aud` 小写加 `key`，例如 `bookkey` |
| `user.id` | 站长类专用的随机值 | 锁屏类专用的随机值 | 每个 `aud` 各自的随机值 |

不同的 `user.id` 让密码管理器把它们存成独立的条目，一眼就能分清哪把是站长、哪把是解锁、哪把是哪个应用。

### 5.3 应用白名单

应用列表是主站的一份配置（目前只有 `book`）。新增应用只需要加一行：`aud`、允许的 `scope`、允许的 `return` origin。注册不在白名单里的 `aud` 返回 400；签发时 `aud`、`scope`、`return` 任一不在白名单内一律拒绝。

## 6. 完整鉴权流程

本节按用户实际经历的顺序，描述从打开网站到完成敏感操作的每一步。

### 6.1 入口与锁屏

1. 访问任一站点。每个请求先经过该站的中间件，检查 `sgx-verified`：签名、未过期、`epoch` 不低于主站当前值。
2. 没有有效会话：
   - 页面请求跳到主站锁屏 `https://styrigx.com/?lock=1`，并带上原地址作为 `return`；
   - API 请求返回 `401` JSON，**禁止**返回 302。理由：前端 `fetch` 会静默跟随 302，拿到一页锁屏 HTML，表现为莫名其妙的「加载失败」。
3. 锁屏只显示头像。点击头像弹出的选项按锁屏凭证的配置决定，「访客进入」始终在第一位：
   - 两者都有 → 访客进入 / 通行密钥 / 密码 / 重置锁屏
   - 仅通行密钥 → 访客进入 / 通行密钥 / 重置锁屏
   - 仅密码 → 访客进入 / 密码 / 重置锁屏
   - 都没设置 → 访客进入 / 根凭证（不显示重置锁屏）
   
   配置状态以服务端为准；读取失败按「已配置」处理，避免暴露根凭证入口。

### 6.2 访客进入

1. 选「访客进入」，完成 Cloudflare Turnstile 人机验证。
2. 主站 `/api/verify` 向 Cloudflare 复核结果，通过后签发 `role=visitor` 的 `sgx-verified`，有效期 1 小时。
3. 访客可以访问：桌面与应用、博客、书库的公开内容、设置及其子页面、安全与隐私总览、我的文件，以及「立即锁定」（只锁当前设备）。
4. 访客**不能**访问：站长凭证管理、管理凭证、锁定所有设备，以及对应的管理 API。安全与隐私页上，访客看到的三个入口（站长凭证 / 管理凭证 / 立即锁定）与站长看到的外观完全一致，但站长凭证和管理凭证入口是假入口：无论提交什么都返回通用失败提示，不做任何实际验证。

### 6.3 主人解锁

1. 选「通行密钥」：用锁屏类通行密钥完成 WebAuthn 认证；或选「密码」：提交锁屏密码。
2. 通过后主站签发 `role=owner` 的 `sgx-verified`，有效期 12 小时，期间三站都不再要求验证。
3. 密码验证**必须**限流。通行密钥解锁不受密码限流影响，所有者不会被别人刷失败次数锁在门外。
4. 锁屏凭证都没设置时，选「根凭证」：提交根凭证，通过后换取站长会话（1 小时），进入站长模式。只要配置了任一锁屏凭证，这个入口就不再显示。

### 6.4 访客就地升级

1. 安全与隐私总览页上，主人专属的入口显示锁形图标。
2. 访客点击时，**不跳转**，就地弹出升级验证层，只显示「通行密钥」和「密码」两项，不显示访客入口。
3. 验证通过后主站把当前会话换成 owner 会话，页面直接进入目标设置。
4. 访客直接打开主人专属路径，或带着 `return=<主人专属路径>` 回到首页时，**最多跳转一次**，最终停在升级验证层。理由：「专属页把访客送回首页、首页又把有效会话送回原路径」会形成重定向循环，必须由一方终止。

### 6.5 主站安全设置（STEPUP）

安全与隐私页只有三个入口：**站长凭证**、**管理凭证**、**立即锁定**。

**入口一「站长凭证」**：管理站长类通行密钥和 owner 密码。

1. 需要有效的锁屏会话（owner）。点击后弹窗要求输入根凭证。
2. 根凭证通过后，主站签发 `sgx-stepup`（`by=root, scope=root`，10 分钟），进入站长凭证管理。
3. 在这里可以增删 owner 通行密钥、设置或修改 owner 密码。owner 密码不得与锁屏密码相同。

**入口二「管理凭证」**：管理锁屏凭证、应用凭证、会话。

1. 需要有效的锁屏会话（owner）。点击后弹窗要求二次验证，按钮按站长凭证的配置决定：
   - 什么都没设置 → 只显示「根凭证」
   - 只设了通行密钥 → 「通行密钥验证」
   - 只设了密码 → 「密码验证」
   - 两个都设了 → 两个都显示，不显示根凭证
2. 站长凭证通过后，主站签发 `sgx-stepup`（`by=owner, scope=keys`，10 分钟），进入管理。
3. 在这里可以：增删锁屏类通行密钥、增删应用类通行密钥、设置锁屏密码、查看会话、锁定所有设备。
4. 一旦配置了站长凭证，根凭证对「管理凭证」入口自动失效（接管）。

`sgx-stepup` 的格式为 `by.scope.epoch.iat.exp.sig`，其中 `by` 为 `root` 或 `owner`，`scope` 为 `root`、`keys` 或 `lockreset`。接口校验 `scope`，不匹配一律 403。

**立即锁定**：紧急按钮，只会减少权限，不设门槛，访客和站长都能用。

例外，各有理由：

- **第一把站长凭证没有例外**：还没有站长凭证时，「管理凭证」入口只显示「根凭证」，用根凭证完成二次验证。
- **锁定所有设备**：在「管理凭证」入口内，紧急按钮，不设门槛，访客除外。
- **禁止删除最后一种主人解锁方式**：没有锁屏密码时，不能删除最后一把锁屏类通行密钥。

### 6.6 子站敏感操作（APP，以 book 上传为例）

1. book 上传、删除、换封面前，发现没有有效 `sgx-app` → 跳到 `https://styrigx.com/app-verify/?aud=book&scope=upload&return=<book 地址>`。
2. 主站校验：owner 会话；`aud`、`scope` 在白名单内；`return` 解析后 origin 严格等于该应用登记的 origin，否则拒绝。
3. 主站用该 `aud` 的应用类通行密钥做 WebAuthn 认证，强制 UV。该应用还没有应用类通行密钥时，提示「先在 安全与隐私 → 管理凭证 中添加 book 的钥匙」，不提供密码选项。
4. 通过后前端调用 `POST /api/app-token`。接口要求请求 `Origin` 为 `https://styrigx.com`、`Content-Type` 为 `application/json`（CSRF 防护），用 APP 私钥签发 `sgx-app`，写入 cookie 后跳回 `return`。**全程不需要 `sgx-stepup`。**
5. book 用 APP 公钥验签，检查 `role=owner`、`aud=book`、`scope`、未过期、`epoch` 和 `appEpoch` 不低于主站当前值，通过后执行操作。
6. 大文件上传：通行证只在创建上传任务时检查。任务在 book 的数据库登记 2 小时，并记下签发时的 `appEpoch`；后续分片、完成、取消只需要 owner 会话加有效任务号，且登记的 `appEpoch` 仍是当前值。理由：大文件不会因为 10 分钟通行证过期而中断，删除钥匙又能立刻掐断进行中的任务。

### 6.7 锁屏、锁定所有设备与多标签同步

| 动作 | 谁能用 | 效果 |
|---|---|---|
| 立即锁定 | owner、visitor | 清除当前设备的会话 cookie，只影响这一台设备 |
| 锁定所有设备 | 仅 owner | 会话纪元加一，所有设备上的三种凭证同时失效 |

多标签同步**禁止**依赖 BroadcastChannel、localStorage 或前端内存，各标签在 `visibilitychange`、`pageshow`、`focus` 时向服务端复查会话。理由：跨子域的标签之间没有可靠的前端通道，服务端是唯一的事实来源。

### 6.8 根凭证（恢复用）

根凭证是最后的恢复手段，用于站长凭证和锁屏凭证都不可用时找回控制权。

1. `POST /api/root-auth { key }`：只接受 POST，校验 Origin，恒定时间比较。缺 Origin 返回 403；根凭证错误返回 401。
2. 通过后按场景签发不同 `scope` 的 `sgx-stepup`（10 分钟）：
   - 有锁屏会话时 → `by=root, scope=root`，用于进入「站长凭证」入口；
   - 无锁屏会话但锁屏凭证均未配置时 → 换取站长会话（1 小时），进入站长模式。
3. 根凭证**永远不能**签发 `sgx-app`；也**不能**单独用于解锁、进入「管理凭证」入口或重置锁屏（恢复开关的特殊情况见 6.9）。
4. 失败限流：同一 IP 连错 5 次锁 15 分钟；全站每小时失败 20 次暂停验证 1 小时；超限返回 `429`。限流计数的读写出错一律拒绝（`503`）。
5. 每次使用（成功、失败、被限流）都写审计记录，只记时间、IP 前缀和是否成功，保留 7 天。审计列表可在「管理凭证」入口内查看。
6. 缺根凭证或相关私钥时拒绝（500 或 503）。
7. 更换根凭证后需要重新部署主站才生效。

### 6.9 重置锁屏

用于锁屏凭证（通行密钥或密码）丢失时的恢复。流程固定为两步，缺一不可：

1. **第一步：根凭证**。在锁屏的「重置锁屏」入口提交根凭证。根凭证错误时返回通用失败提示，不透露任何配置信息。
2. **第二步**：根凭证通过后，服务端检查恢复开关：
   - 恢复开关有效（由托管平台账号临时开启、24 小时内有效、仅限一次）→ 直接签发 `lockreset` 票据；
   - 否则 → 要求站长凭证（按配置显示通行密钥和/或密码按钮），通过后签发 `lockreset` 票据。
   
   站长凭证未配置且恢复开关无效时，重置不可用，返回通用失败提示，不说明原因。

3. 持 `lockreset` 票据只能重设锁屏通行密钥和锁屏密码：**不能**签发 `sgx-verified`，**不能**进入主页面，**不能**触碰应用凭证、会话或两个管理入口。完成后会话纪元推进，旧会话全部失效，再用新配置的锁屏凭证正常解锁。
4. 重置流程全程计入根凭证限速；失败一律返回通用提示，不区分是根凭证错、开关无效还是站长凭证错。

## 7. 存放与配置

### 7.1 各站变量

| 项目 | 变量 |
|---|---|
| 主站 | `SGX_LOCK_PRIVATE`、`SGX_APP_PRIVATE`、`SGX_STEPUP_PRIVATE`、`SGX_LOCK_PUBLIC`、`SGX_STEPUP_PUBLIC`、`SGX_APP_PUBLIC`（只供 `/api/diag-keys` 自检）、`SGX_ROOT_KEY`、`SGX_PW_PEPPER`、`SGX_SITE=space` |
| blog | `SGX_LOCK_PUBLIC`、`SGX_SITE=blog` |
| book | `SGX_LOCK_PUBLIC`、`SGX_APP_PUBLIC`、`SGX_SITE=book` |
| 以后的子站 | `SGX_LOCK_PUBLIC`、`SGX_SITE`；需要敏感操作时加入应用白名单并配 `SGX_APP_PUBLIC` |

### 7.2 规则

- 私钥**必须**用 Secret 配置。公钥不是秘密，可以用 Text（控制台可见，便于核对），也可以用 Secret；当项目的纯文本变量由 `wrangler.toml` 管理、控制台只允许添加 Secret 时，用 Secret。无论哪种，公钥**禁止**写进仓库或 `wrangler.toml`，保证线上只有一个事实来源。
- 子站**禁止**出现任何 `*_PRIVATE`、任何 `SGX_STEPUP_*` 和 `SGX_ROOT_KEY`，只持公钥。CI 对子站源码做静态检查，出现即构建失败。子站的 `SGX_SITE` 缺失或不等于本站名时 fail closed：blog 一律跳主站锁屏，book 一律返回 `500`。
- 主站的 `/api/app-token` 链路**禁止**引用主站密钥和 `SGX_ROOT_KEY`；`sgx-stepup` 的验签只允许出现在 `owner-passkey`、`owner-password`、`stepup` 三个接口。由 CI 里的静态测试检查。
- 三站可通过主站 `/api/key-fingerprint` 和各站同名接口核对锁屏公钥指纹（SHA-256 前 16 位），只暴露公钥哈希。
- 私钥另存一份在密码管理器，按「锁屏密钥 / APP 密钥 / 主站密钥」分条保存。
- 生产与预览环境的密钥完全分开；CI 每次临时生成，用完即弃。
- 每个带函数的 Pages 项目**必须**把超额行为设为 **Fail closed**。理由：设为 Fail open 时，免费额度用尽后请求会绕过函数直接返回静态资源，等于绕过了锁屏。space、blog、book 三个项目均已设为 Fail closed。

生成方式：

```
openssl genpkey -algorithm ed25519 -out <用途>.key
openssl pkey -in <用途>.key -pubout -out <用途>.pub
```

## 8. 撤销：会话纪元与应用纪元

主站在 KV 里保存两类单调递增的整数：

| 纪元 | KV 键 | 何时加一 | 作废什么 |
|---|---|---|---|
| 会话纪元 | `session-epoch` | 锁定所有设备、设置或修改密码、删除密码、删除锁屏类通行密钥 | 全部三种凭证 |
| 应用纪元 | `app-epoch:<aud>` | 删除该应用的任一应用类通行密钥（只推进应用纪元，不推进会话纪元） | 该应用的 `sgx-app` 和进行中的上传任务 |

为什么另设应用纪元而不复用会话纪元：删除 book 的钥匙只应该让 book 的通行证失效，不应该把所有设备一起锁掉。按应用分开，也让删除 book 的钥匙不影响以后 music 的通行证。

子站通过主站 `/api/session-epoch` 获取最新值（返回会话纪元和各应用纪元），内存缓存 60 秒，所以撤销最多 60 秒内在子站生效。读取失败且无缓存时拒绝；KV 读取出错时接口返回 `503`，绝不当作 0，也绝不写入更小的值。

## 9. 失败行为（fail closed）

| 情况 | 行为 |
|---|---|
| 缺锁屏公钥 | 页面跳锁屏，API 401，只放白名单路径 |
| 缺任一私钥 | 拒绝签发对应凭证，返回 500，不降级 |
| 缺 APP 公钥 | 子站敏感操作一律 403 |
| 缺主站公钥或私钥 | 安全设置一律 403 或 500，根凭证恢复也拒绝（500）；锁屏解锁和 APP 验证不受影响 |
| 缺 `SGX_ROOT_KEY` | `/api/root-auth` 返回 500 |
| 根凭证限流计数读写出错 | 503，拒绝 |
| 缺 `SGX_PW_PEPPER` | 密码相关接口拒绝（500），不降级为无 pepper 哈希 |
| 子站 `SGX_SITE` 缺失或不符 | blog 跳锁屏，book 返回 500 |
| 未登录调用 `/api/diag-keys` | 401 |
| 纪元拿不到且无缓存 | 拒绝 |
| KV 读取出错 | 503，不写入 |
| 签名不符、过期、纪元过旧、aud 或 scope 不符、role 不是 owner | 拒绝 |
| 通行密钥分类或 aud 不符 | 拒绝 |
| `return` 不在白名单 | 拒绝，不跳转 |
| 平台额度耗尽 | Fail closed，不出静态页 |

没有任何「未配置就放行」的开关，测试也不靠放行通过。

## 10. 轮换与事故响应

**计划轮换**（建议每年一次，或更换设备、协作方式时）：

1. 生成新密钥对。
2. 在对应项目同时配上新私钥和新公钥。
3. 部署主站，再部署子站。
4. 会话纪元加一（换 APP 密钥时也可只加对应应用纪元），让旧凭证全部失效。
5. 所有设备重新解锁，确认正常后从密码管理器删除旧密钥。

**紧急轮换**（怀疑私钥泄露）：立即执行上面 1 至 4 步，先换密钥再排查原因；只换出问题的那一对，其余两对不动。

**通行密钥丢失**（设备丢失）：用另一台设备或密码解锁 → 做一次二次验证 → 删除丢失设备上的通行密钥（删除锁屏类会自动推进会话纪元，所有设备需要重新解锁；删除应用类只推进该应用的应用纪元）。所有解锁方式都丢失时，用根凭证进入重置流程（见 6.9），再重设锁屏凭证。

**根凭证轮换**：在主站 Secret 里换掉 `SGX_ROOT_KEY`，然后重新部署主站。已签发的凭证不受影响；需要一并作废时，再锁定所有设备。

## 11. 验收要求

每个涉及密钥或鉴权的改动都**必须**有接入 CI 的功能测试，只在本地跑过不算数。

- 缺变量 fail closed。
- 过期、纪元变更、篡改、伪造签名、visitor 全部被拒。
- 跨用途被拒：`sgx-verified` 不能当 `sgx-app` 或 `sgx-stepup`；`sgx-stepup` 不能当 `sgx-app`；aud 或 scope 不符被拒。
- 通行密钥分类：站长类、锁屏类、应用类各自的 challenge 只列出对应 `class`；锁屏类在 `/app-verify/` 被拒；应用类在锁屏被拒；`aud=book` 的凭据验证 `aud=music` 被拒；不在白名单的 `aud` 注册返回 400；锁屏类通行密钥不能换 `sgx-stepup`。
- 解耦：没有 `sgx-stepup` 时，应用类通行密钥仍能签发 `sgx-app`；没有 owner 会话时注册任一类通行密钥返回 401；没有 `sgx-stepup` 时增删任一类通行密钥返回 403。
- 撤销：删除应用类通行密钥后，旧 `sgx-app` 在子站返回 403，进行中的上传任务被拒。
- 根凭证：正确 → 按场景签发对应 `scope` 的 `sgx-stepup` 或站长会话；错误 → 401 并计数；超限 → 429；缺 `SGX_ROOT_KEY` 或 `SGX_STEPUP_PRIVATE` → 拒绝；KV 出错 fail closed；每次使用都写审计记录；`/api/app-token` 不引用 `SGX_ROOT_KEY`；缺 Origin 返回 403。
- 重置锁屏：根凭证 → 恢复开关或站长凭证 → `lockreset` 票据；票据只能重设锁屏凭证，不能进主页；失败一律通用提示，不区分原因。
- 删除应用类通行密钥只推进 `app-epoch:<aud>`，不推进会话纪元。
- 自检：`/api/diag-keys` 未登录返回 401；三对密钥匹配返回 true，错配返回 false，缺失返回 "missing"。
- 注册参数：`user.displayName` 为 `Sloan Gray`；`user.name` 分别为 `ownerkey`、`lockkey` 和 `<aud>key`（如 `bookkey`）。
- 访客范围：访客能打开设置、安全总览和我的文件，能立即锁定；主人专属路径最多跳转一次并停在升级层；主人专属 API 对访客返回 403；访客看到的安全页三个入口与站长外观一致。
- 锁屏入口：按锁屏凭证配置显示四种状态；读取失败按已配置处理，不暴露根凭证入口。
- 跨站契约：主站签发的 `sgx-verified` 能被每个子站解析。
- 有效凭证通过；上传任务在通行证过期后仍能完成。

合并标准为正式 CI 全绿。修复实现，**禁止**改测试去迎合实现；视觉基线的变化不能替代功能断言。

## 附录

### A. 术语

- **Ed25519**：一种椭圆曲线签名算法，密钥短、验证快、不需要额外参数。
- **通行密钥（passkey）**：基于 WebAuthn 的无密码凭据，私钥留在设备或密码管理器里，网站只保存公钥。
- **UV（User Verification）**：认证时要求本人生物识别或 PIN，而不仅仅是「设备在场」。
- **fail closed**：出错或缺配置时拒绝，而不是放行。
- **会话纪元 / 应用纪元**：用来一次性作废已签发凭证的单调递增整数。
- **aud / scope**：通行证的使用对象和用途。
- **Turnstile**：Cloudflare 的人机验证，本站只用它签发访客会话。
