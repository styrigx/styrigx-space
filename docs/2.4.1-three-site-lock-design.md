# 2.4.1 三站真实锁屏方案文档

> 只文档，不写代码。等 Gray 真机验收通过后再开分支实现。
> 依据：3.0 任务书 §三「2.4.1 锁屏真实拦截 + 三站共享」。

## 一、目标

1. 主站（styrigx.com）：没有有效会话时，服务端只返回锁屏页，不返回任何正文（当前是前端 JS 跳转，可被 curl 绕过）。
2. 博客（blog.styrigx.com）、书库（book.styrigx.com）：共用同一套会话，未验证时 302 到主站锁屏，验证后跳回原地址。

## 二、共享 Middleware

### 2.1 位置

- 主站：`styrigx-space/functions/_middleware.js`（已存在 P0-3 的域名隔离，需扩展）。
- 博客：`styrigx-blog/functions/_middleware.js`（新建）。
- 书库：`styrigx-book/functions/_middleware.js`（新建）。

三站共用同一份逻辑，通过环境变量区分角色（`SGX_SITE=portal|blog|book`）。

### 2.2 会话 Cookie（Ed25519 非对称方案）

**不要三站共用 SESSION_SECRET**（任一站泄露都能伪造主站会话）。

- 主站用 **Ed25519 私钥**签发 `.styrigx.com` cookie。
- blog/book 只配**公钥**验签，不持有能签发会话的密钥。
- Cookie 内容：`epoch.exp.sig`，其中：
  - `epoch`：session epoch（整数，主站 KV `session-epoch`，初始 0）
  - `exp`：过期时间戳（12 小时，`Date.now() + 12*3600*1000`）
  - `sig`：Ed25519 私钥对 `epoch.exp` 的签名（base64url）
- Cookie 属性：`HttpOnly; Secure; SameSite=Lax; Domain=.styrigx.com; Path=/`。
- 验证：blog/book 用公钥验签 → 检查 `exp` 未过期 → 检查 `epoch` >= 本地缓存的最新 epoch。

### 2.3 主站逻辑（SGX_SITE=portal）

```
请求 → 检查 sgx-verified cookie
  → 有效（验签通过、未过期、epoch 当前）：next()
  → 无效/缺失：
    → 白名单路径：next()
    → 其他：返回锁屏页 HTML（200，不 302，避免 SEO 跳转链）
```

白名单（只放行验证必需）：
- `/api/owner-auth`、`/api/owner-password`、`/api/owner-passkey`、`/api/owner-status`
- `/api/session-epoch`（公开接口，返回当前 epoch，供 blog/book 缓存，见 §2.5）
- `/api/turnstile-verify`（如有）
- 锁屏页自身 `/`、`/?lock=1`、`/en/`（英文锁屏）
- 静态资源：`/assets/*`、`/*.css`、`/*.js`、`/*.woff2`、`/*.png`、`/*.svg`、`/*.ico`
- `/favicon.ico`、`/robots.txt`

锁屏页 HTML：复用现有 `layouts/index.html` 的锁屏分支，确保不带任何正文内容。

### 2.4 博客/书库逻辑（SGX_SITE=blog|book）

```
请求 → 检查 sgx-verified cookie
  → 有效（Ed25519 公钥验签通过、未过期、epoch >= 缓存的最新 epoch）：next()
  → 无效/缺失/过期：
    → 白名单（同上，路径按本站调整）：next()
    → 其他：302 到 https://styrigx.com/?lock=1&return=<原地址编码>
```

`return` 白名单：只允许 `*.styrigx.com`（防开放重定向）。主站验证通过后：
```
→ 检查 return 参数在白名单内：302 到 return
→ 否则：302 到 https://styrigx.com/
```

### 2.5 Epoch 同步（「立即锁定并退出所有设备」）

主站「立即锁定」时：`session-epoch` +1（存主站 KV），旧 epoch 的 cookie 全部失效。

blog/book 需要知道最新 epoch，采用**方案 A：主站公开接口 + 短缓存**。

- 主站新增 `GET /api/session-epoch` → 返回 `{"epoch": N}`，`Cache-Control: public, max-age=60`。
- blog/book 的 middleware 每次验证时：
  - 先查本地缓存（内存，TTL 60 秒）。
  - 缓存过期则调主站接口刷新。
- **最长延迟**：60 秒（blog/book 本地缓存）+ 60 秒（KV 跨边缘传播，主站写 KV 后各边缘可见时间）≈ **约 2 分钟**。
  - 注：Cloudflare KV 跨边缘可见通常要 60 秒以上，写 10 秒太乐观。
- **Fail closed**：blog/book 拿不到 epoch（主站接口超时/失败且本地无缓存）时，**一律拒绝**，不放行。这是安全默认值。

**为什么不用 Durable Object**：DO 能提供强一致读（无 60 秒延迟），但引入新的运行时组件、增加运维复杂度。当前只有 Gray 一个管理员，「退出所有设备」是低频操作，2 分钟延迟可接受。后续如需更低延迟再迁移到 DO。

## 三、apps.yaml 登记

在主站 `data/apps.yaml`（或新建 `data/sites.yaml`）登记三站：

```yaml
sites:
  - id: portal
    name: 主站
    host: styrigx.com
    lock: local  # 本地锁屏
  - id: blog
    name: 博客
    host: blog.styrigx.com
    lock: redirect  # 跳主站锁屏
  - id: book
    name: 书库
    host: book.styrigx.com
    lock: redirect
```

用途：生成 `return` 白名单、文档、未来设置页展示。

## 四、接入步骤（blog/book）

1. 在各自仓库新建 `functions/_middleware.js`，复制主站逻辑（或抽成 npm 包，2.4.2 再做）。
2. 配置环境变量 `SGX_SITE=blog|book`。
3. 确保 `SESSION_SECRET` 与主站相同（从主站复制）。
4. 部署后验证：不带 cookie 访问文章页 → 302 到主站锁屏。

## 五、需要 Gray 在 Cloudflare 后台动手的地方

### 主站（styrigx-space）

1. **Environment variables → Production**：
   - `SGX_SITE` = `portal`
   - 生成 Ed25519 密钥对（本地生成，不要在线工具）：
     ```bash
     openssl genpkey -algorithm ed25519 -out ed25519-private.pem
     openssl pkey -in ed25519-private.pem -pubout -out ed25519-public.pem
     ```
   - `SGX_ED25519_PRIVATE` = 私钥 PEM 内容（secret_text，只配在主站）
   - `SGX_ED25519_PUBLIC` = 公钥 PEM 内容（plain_text，主站也要配，供自验）
   - 确认 `SESSION_SECRET` 仍存在（主站内部接口仍用 HMAC，如 owner-auth token）。
2. **Custom domains**：确认 `styrigx.com` 已绑定（已有）。

### 博客（styrigx-blog）

1. **Environment variables → Production**：
   - `SGX_SITE` = `blog`
   - `SGX_ED25519_PUBLIC` = 主站的公钥 PEM 内容（plain_text，只配公钥）
   - **不要配** `SGX_ED25519_PRIVATE` 和 `SESSION_SECRET`（blog 不签发会话）
2. **Pages Functions**：确认已启用（默认启用）。

### 书库（styrigx-book）

1. **Environment variables → Production**：
   - `SGX_SITE` = `book`
   - `SGX_ED25519_PUBLIC` = 主站的公钥 PEM 内容（plain_text）
   - **不要配**私钥
2. 同上确认 Functions 启用。

### 三站共同

1. **robots.txt**：三站全站 `Disallow: /`（任务书要求，防爬虫存档锁屏后的内容）。
   - 主站：`static/robots.txt` 已有，需更新。
   - 博客/书库：各自加。

## 六、验收标准

1. `curl https://styrigx.com/` 不带 cookie → 返回锁屏页 HTML，不含正文。
2. 伪造/过期 `sgx-verified` → 同上。
3. `curl https://blog.styrigx.com/post/xxx` 不带 cookie → 302 到 `https://styrigx.com/?lock=1&return=...`。
4. 主站验证通过后带 `?return=https://blog.styrigx.com/post/xxx` → 跳回原文。
5. `return=https://evil.com` → 跳回主站首页（不跳外部）。
6. 关闭浏览器后 cookie 失效（会话 cookie 无过期时间）。

## 七、风险与注意

1. **私钥保护**：Ed25519 私钥只存在主站，blog/book 只有公钥。私钥泄露则攻击者可签发任意会话 → 私钥只存 Cloudflare secret，后台权限收紧。
2. **Epoch 同步延迟**：「退出所有设备」后，blog/book 最多 70 秒后旧会话失效（§2.5 方案 A）。如需立即失效，blog/book 可每次请求都调主站接口（增加延迟，不推荐）。
3. **Cookie 过期**：12 小时，到期后 blog/book 的 middleware 会 302 到主站重新解锁（`?lock=1&return=原地址`），用户体验：每 12 小时需重新验证一次。
4. **KV 共享**：不需要。blog/book 无状态验证（公钥验签 + 主站 epoch 接口），无需共享 KV。
5. **预览环境**：blog/book 的预览部署也应配 `SGX_SITE` 和公钥，否则 middleware 不知道自己是谁。CI 的 PATCH 方案可复用。
