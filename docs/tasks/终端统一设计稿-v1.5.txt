# 终端统一 设计稿 v1.5（给 Gray / Muse 审）

> 基于 `styrigx/styrigx-space` main `225888e9`（#371）。本稿只定方案：不写代码、不开 PR。测试归 Muse；不重拍视觉基线。

## 0. 原则（Gray 已定）

1. **五个 tty**（Gray 01:59 定：盾牌、账号不合并）：tty1 锁屏、tty2 主页（首屏终端 + 全站 Ctrl K 抽屉）、tty3 盾牌下拉、tty4 AI、tty5 账号（头像下拉）。新增 `tty` 命令：显示当前 tty，`tty <n>` 切换。
2. **一个引擎 + 一张命令注册表**：每条命令一个对象（名称、可用 tty、参数、补全、man 页、run）。
3. **只有 tty1 按入口限制命令**（白名单：解锁相关、help、man、clear、tty），锁屏也只加载白名单命令的代码。tty2/3/4/5 用同一张全表。服务端鉴权不变：登录、reauth、reset 照旧由 Worker 判，前端白名单不算鉴权。
4. **命令行不跳页**：唯一跳到 GUI 的是 `open <路径>`（类似 xdg-open）；`cd` / `ls` / `pwd` 只在命令行里走虚拟目录。reauth、确认、遮挡输入、文件选择、复制链接都在当前 tty 里原地完成。
5. **man**：`man <命令>` 每条一页，格式同现有锁屏的 `man styrigx`（Gray 口中的「man space」）：`NAME(1)` / NAME / SYNOPSIS / DESCRIPTION / SEE ALSO / `(END)`，按 q 退出。光打 `man` 出索引；`help` 是简短列表。
6. **外观一律不动**：布局、配色、字体、尺寸、DOM 结构、类名都不改。视觉测试应当没有 diff。
7. **代码按职责分文件夹、分文件。**
8. **只借 Linux 终端的习惯，不做完整 shell**：借的是「命令 + 参数」、man、tab 补全、历史、提示符。

### 不做清单
| 不做 | 说明 |
|---|---|
| 管道 `\|` | 不解析，`\|` 当普通字符，原样进参数 |
| 重定向 `> >> <` | 同上 |
| 变量 `$X`、`export`、命令替换 `` `…` `` / `$(…)` | 不展开 |
| 脚本 / 多条命令 `;` `&&` `\|\|`、`source` | 一行只跑一条命令 |
| 通配符 `* ? [..]`、花括号展开 | 不展开，当字面量 |
| 引号转义、别名定义 `alias`、作业控制 `& fg bg` | 参数一律按空白切开；名称里不许有空格（sub-add 等命令会校验） |

### 2.2 tty 切换与状态
- `tty.js` 记住当前 tty。每个宿主挂载时登记 `{n, show(), ps(), surface}`。
- `tty`：显示 `tty2`（简化版：Linux 的 tty 输出设备路径如 `/dev/pts/0`，这里只输出编号名）。`tty 3` 打开 tty3 的宿主（盾牌下拉），`tty 5` 打开账号下拉，`tty 4` 打开 AI 窗口，`tty 2` 打开 Ctrl K 抽屉（在主页则聚焦首屏终端）。这是切 tty，不算跳页，也不跳 URL。
- tty1 里 `tty` 只显示；`tty <n>` 输出 `tty: permission denied`，因为还没进站。
- `sudo root …` / `sudo styrigx …` 不再打开下拉，而是在当前 tty 原地跑验证（原则 4）。要进账号的 GUI 层就用 `open ~/account/security` 这类命令。
- 每个 tty 的 cwd 和输入模式各自保存，切 tty 不会互相干扰。

### 2.3 补全 / 历史 / 提示符怎么统一
- **补全**：第 1 个词从 `registry.names(tty)` 里取；后面的词调用该命令的 `complete(args, ctx)`（虚拟路径、来源名等）。五个 tty 都有 Tab 补全（tty4 只在 `$ ` 开头时）。影子（淡色提示）只在有 `[data-term-ghost]` 元素的 tty2 显示，其余 tty 没有这个元素，外观不变。
- **历史**：`history.js` 统一处理 ↑↓、草稿、去掉相邻重复、上限 50 条。tty2 继续用 `sgx-term-hist`（键名不变）；tty3 用 `sgx-term-hist-3`（sessionStorage）；tty1 只放内存（锁屏不落盘）。秘密模式下的输入一律不进历史。

**五个 tty 一览**
| tty | 宿主 | 提示符（原样） | Tab 补全 | 历史 |
|---|---|---|---|---|
| tty1 | 锁屏 | `entry@space:~$` / `reset@space:~#` | 有（只补白名单命令） | 只在内存 |
| tty2 | 主页首屏 + Ctrl K 抽屉 | `styrigx@space:~$` / `root@account:~#`，带 cwd | 有，带淡色影子 | sessionStorage `sgx-term-hist`（键名不变） |
| tty3 | 盾牌下拉 | `styrigx@space:~#` | 有 | sessionStorage `sgx-term-hist-3` |
| tty4 | AI 窗口（`$ ` 前缀才是命令） | 无（沿用 AI 输入框） | `$ ` 开头时有，无影子 | 命令走 sessionStorage `sgx-term-hist-4`；普通提问仍走 AI 自己的 `sgx-ai-history`，两者不混 |
| tty5 | 账号头像下拉 | `login@account:~$` / `root@account:~#` / `reset@account:~#` | 有 | sessionStorage `sgx-term-hist-5` |
所有 tty：秘密输入、选择输入不进历史。

**tty4 的 ↑↓ 召回哪个历史**：看输入框当前内容。以 `$` 开头（含只敲了 `$`）→ 召回命令历史 `sgx-term-hist-4`，召回的条目带 `$ ` 前缀放回输入框；其余情况（含空输入框）→ 照旧召回 AI 提问历史 `sgx-ai-history`，现有行为不变。两条历史各自独立，不互相穿插。
- **提示符**：`prompt.js` 把现有字符串原样集中起来，每个 tty 的规则不变（见 1.1）。外观零变化。
- **打错提示**：候选从注册表生成（命令名 + 每条命令声明的 `examples`），不再到处手写候选数组。

## 3. 命令注册表 schema（示例）
```js
// cmds/sub/sub-upload.js
export default {
  name: 'sub-upload',
  tty: 'full',                 // 'full' = tty2/3/4/5；tty1 白名单命令写 ['tty1','full']
  args: [{ name: 'name', required: true, kind: 'source' }],   // kind 决定补全
  examples: ['sub-upload home'],                               // 给打错提示和 help 用
  help: 'help.subUpload',      // help 列表那一行（i18n 键）
  man: () => import('../../man/sub-upload.js'),                // 懒加载，不进首包
  complete: (args, ctx) => ctx.sub.sourceNames(),              // 来源名（用户自定义，和文件名无关）
  needs: ['account'],          // 前端只用来给提示；真正的鉴权在服务端
  async run(args, io, ctx) {   // io = 引擎给的输出/输入能力：out/ok/err/pick/ask(secret)/busy/progress/filePick
    const f = await io.filePick({ accept: '.yaml,.yml,.txt' });
    if (!f) return;
    const r = await ctx.sub.upload(args[0], f, (p) => io.progress(p)); // [######----] 60%
    io.ok(io.tf('sub.uploaded', { name: args[0], n: r.nodes }));       // 已上传 <名称> · N 个节点
  },
};
```
- 别名写在 `aliases`（`cls`→clear、`?`→help、`logout`→exit、`sudo -i`→sudo root）。旧的空格写法 `passkey add` 等作为别名保留；正式名改成连字符（`passkey-add`），和 sub-* 的写法一致。
- 有子命令的 `sudo` 用一个对象，在 `run` 里分 `root` / `styrigx`；`man sudo` 一页写全。
- P2 要注册的命令：`sub`（状态）、`sub-key`（要 reauth）、`sub-link`（要 reauth，新链接只显示一次）、`sub-add <名称>`（会话模式，链接用遮挡输入）、`sub-upload <名称>`、`sub-mv <旧名> <新名>`、`sub-on` / `sub-off` / `sub-rm <名称>`、`sub-refresh`。`man sub` 的 SEE ALSO 列出其余 9 条。

## 5. 风险
- **锁屏 tty1 限制**：锁屏 chunk 必须只 import `index-tty1.js`。用构建检查（js-split / esbuild metafile）断言锁屏 chunk 里没有 `cmds/fs|ui|account|sub`。白名单只是减少暴露面，安全仍靠服务端会话、reauth、reset 票。
- **CSP**：Report-Only 的 `script-src 'self' + hash`。新模块都是同源静态文件，没问题；但不许 `eval` / `new Function`，也不许新增内联脚本（否则 hash 会失效）。输出统一走片段 + `textContent`；B、C 原来的 `innerHTML` 会改成片段渲染，但产出的 DOM 必须和原来一样（Muse 的快照测试负责核对）。
- **包体积**：三份合计约 81 KB 源码，去重后应该更小。man 页、sub-upload（文件选择）、passkey 都用 `import()` 懒加载。现在 quick-panel 在每一页都静态引入 terminal.js 和 account/term.js，表做好之后不能把全部命令都塞进 core chunk。以 T1 之前的 chunk 大小为基线，每个 PR 不许变大。
- **现有 e2e 选择器**：`#sgx-entry-cmd`、`#sgx-entry-log`、`#sgx-entry-form[data-mode]`、`[data-term-pick]`、`[data-term-in|out|ps|ghost|kh]`、`.sgx-at-*` / `[data-at-pick|mode|layer]`、`sgx-term-*` 类名全部保留，不改名。
- **gen-shell / shared-shell.test**：放宽 import 约束需要同时改脚本和测试（T1）。ai-panel.js 与 terminal.js 一起在 T1 放宽为只许 import `./term/**`（tty4 要用同一张命令表，见第 7 节第 2 条、8.4）。

## 8. v1.1 补充（Muse 审稿意见）

### 8.1 sub-mv（新增命令，Gray 2026-11-10 02:26 确认：只改名，不做「移动」，因为来源没有可移动的位置）
已写进代理订阅设计 v1.10（§5、§7、§8.1），以那边为准。语义摘要：
- **前提以代理订阅设计 v1.10 为准**（2026-11-10 00:27 Gray 定，覆盖 v1.5）：每源一条链接 `/s/<令牌>/<来源名>`，每个来源单独 age 加密成一份 provider，**不合并、节点名不加 `[来源名]` 前缀**。v1.5 的单条合并下载 `/s/<令牌>` 已废弃。
- `sub-mv <旧名> <新名>`：只改 `sources.name`，**沿用原 id**，成品 `armor`、上次好节点 `last_nodes_enc`、开关状态都保留。不触发刷新：代理订阅设计 v1.7 起不加前缀，来源名不进文件内容，`armor` 原样就是新路径的内容，改完立即生效。
- 新名同样只许 `[A-Za-z0-9_-]`、1–32 位；新名已存在 → 报错 `sub-mv: <新名>: already exists`，不覆盖；旧名不存在 → `sub-mv: <旧名>: no such source`；新旧相同 → 什么都不做。
- **后果**：下载路径是 `/s/<令牌>/<来源名>`，改名后**旧路径立即 404**，手机里那个 provider 的 url 要换成新名。所以执行前二次确认，显示新旧两条路径（令牌部分遮挡）。
- 鉴权：会话（同 sub-add）。
- man sub-mv 写明「改名会让手机里的旧链接失效」。

### 8.2 多词别名的匹配
解析仍只按空白切词。查表规则：**最长前缀**——先拿前 3 个词用 `-` 拼起来查表（含 aliases），没有再试前 2 个、前 1 个；命中后剩下的词作参数。
- `passkey add` → 试 `passkey-add` 命中 → 命令 passkey-add，无参数。
- `passkey rm 2` → `passkey-rm-2` 不中 → `passkey-rm` 命中 → 参数 `2`。
- `sudo root reauth` → `sudo-root-reauth` 不中…→ `sudo` 命中，`root reauth` 作参数（sudo 自己分子命令）。
- 多词别名登记成词数组（如 `sudo -i` → `['sudo','-i']` 指向 `sudo root`），匹配时逐词比较，同样走最长前缀，且先于连字符拼接查。
- 都不中 → `command not found`，打错提示照旧。Muse 测：`passkey add`、`passkey-add`、`passkey rm 2`、`sudo -i` 四种写法。

### 8.4 `$ ` 前缀只在 tty4
`$ `（美元符 + 空格）前缀**只在 tty4 的 AI 输入框**里有意义：用来区分「跑命令」和「问 AI」。tty1/2/3/5 里直接敲命令，不加 `$`；在那些 tty 里打 `$ ls` 就是命令名 `$`，报 command not found。和「不做清单」里的 `$X` 不展开是两回事：tty4 剥掉前缀后，剩下的命令行同样不展开变量。

### 8.5 ask 与跨 tty
`ask <问题>` 不自己发请求：调用 `tty.js` 的 `switchTo(4)` 打开 AI 窗口，再调 tty4 登记的 `submit(text)` 接口把问题作为普通提问发出（不加 `$`）。规则：**跨 tty 只通过 tty.js 登记的接口**（show / submit），命令不直接碰别的宿主的 DOM。`tty 4` = 只打开不发问。
