一、目标
• 一个签发者：@ 前的所有身份由 account worker 统一签发与管理（类比 PAM + /etc/passwd），网关只判定不签发。
• 消除两套会话、两把恢复钥匙、sudo root reauth 与 sudo -v 的重叠。

二、理念
• 设计是取舍，忌照抄：Linux 是多用户平级协作、多 tty；本站是自上而下纵深一体的金字塔，由高向低授权。借 Linux 的词汇（root、su、sudo、组、栈），不借它的平级协作模型（owner/group/other 调解平级用户，本站没有平级）。
• 主机固定 space，提示符 <用户>@space:<路径>；未登录提示符保持现状。
• 日常态是 styrigx@space，只有加权操作才 sudo 或 su root。
• root：唯一超级用户，什么都能干（root ⊇ styrigx），不配个人资料；日常只管用户、凭据、授权与批量/结构删除。
• 普通用户：可多个，由 root 增删授权。styrigx 是第一个，也是站长（名片属于 styrigx）。
• uid（INTEGER 主键，P1 已建）：0 = root，1000 = styrigx，1001 起普通用户；用户名另存且唯一。
• root 与普通用户凭据完全独立（密码、通行密钥各自注册；通行密钥显示名区分 styrigx / root）。
• 权限 = 组，fail-closed：新用户默认无组。
• 恢复钥匙一把，只管 root，放 Cloudflare Secrets Store。普通用户忘密码由 root 重置。
• 分享短链 /s/<码> 整套删除；给别人权限改为 root 建带期限的普通用户。代理订阅 /s/<令牌>/<来源名> 保留。

三、权限模型（附加组式，P2 不升 rwx）
• 路由表 ROUTE_ACCESS 是唯一权限来源：每条路由一个显式档 public / user / 组名 / 站长 / root，未列入一律拒绝。请求方法与权限无关（export 是 GET 但归 root，POST /api/ai 是「用」不是「写」）。
• 判断只在一处：core/groups.js 的 permits()。顺序固定：
  1. 救援会话（rescue 标志）：只认白名单命令所需路由，其余一律拒，不往下走；
  2. root：一律放行，不留例外；
  3. 按路由档判断：public 谁都行；user 任一已登录身份（handler 的 uid 只取服务端会话，自限）；组名看是否在组；站长 = styrigx 的 uid。
• admit() 若自带 root 快速放行，同样先被救援白名单限住。「救援 → root」两步只在 precedence() 一处实现，permits() 与 admit() 共用，不各写一份（Muse 05:51，#397 已落实）；未知档先拒，再进 precedence()。
• 不加数字 gid。需要只读时开新组（如 curio-read：一行 user_groups + 一个路由档），不为此升模型。
• 将来若升 owner/group/other + rwx，先钉死：粒度（按应用还是按收藏夹）、other 语义（以盘点表为准）、名片属主、user 档与 owner 取代还是并存、admit 查询代价、chmod 审计。

四、组
• wheel：可 su root。sudoers：可 sudo。
• listen：听歌。ai：AI 窗口。status：旷野状态卡。
• curio-write、daymark-write：上传、编辑、单条删除（单条收藏、日记条目）。
• 批量/结构删除（整个收藏夹、应用、用户、清空）只属 root。
• 权限层级 = man 索引顺序：root → 站长 styrigx → 普通用户 → 访客，自上而下递减（Gray 11-11 18:40）。
• 自上而下（Gray 11-11 18:26）：后台数据控制（用户与组、设备会话、代理、导入导出、批量删除）一律 root 档，站长用 sudo 提权、不必 su root；整站内容只有站长与 root 能写，其余普通用户只读。
• 数字健康整套删除（上报、接口、展示、数据表；删表 SQL 随删除 PR 写成文件，部署绿后执行，不再逐条等 Gray 批，Gray 11-11 20:15）（Gray 11-11 18:26；无意义装饰仅此一项，18:37）。页面：主页 [04] 卡与旷野 #screen-time 拿掉，后续编号前移；/wellbeing/ 跳转一起删（Gray 11-11 19:59）。
• 进站审计接口（/api/space-audit）与状态页审计卡保留（Gray 18:37 只点名删数字健康），恢复写入：记录 v6 的 su / sudo，字段按第十节审计条（Gray 11-11 19:59）。
• styrigx 默认：wheel、sudoers、listen、ai、status、curio-write、daymark-write。
• 普通用户（uid 1001 起，含临时用户）只给只读组 listen、ai、status，代码拒绝加入 wheel、sudoers、写组；写接口不放权，只有站长 styrigx 与 root（Gray 11-11 18:10，自上而下，不加新组）。普通用户只能 passwd 改自己密码、看 root 给的组与公开内容；奇趣/日刻私密条目与 AI 私密内容只给站长与 root。
• ask：按本节 ai 组，ai 组成员的 man 都列出 ask；私密内容仍只给站长与 root（Gray 11-11 19:59）。
• man 索引按 root → 站长 → 普通用户 → 访客分段，各人只看到自己这一层及以下的命令，root 看全部（Gray 11-11 19:59）。

六、身份切换
• su <用户>：输目标用户的凭据。访客可 su 到普通用户。
• su root：仅 wheel 用户可用，输 root 的凭据。root 代码级禁止公开登录：访客发起的签发绝不签 uid=root，公开登录端点拒收 root 凭据。
• 普通用户态不能 su 到另一个普通用户，要换先 exit 回访客。
• sudo <命令>：sudoers 用户每次输自己的凭据，借 root 执行一条，不发票据，不压栈。只有 su 压栈。
• exit：弹一层（root → 普通用户 → 访客；救援直接回访客）。lock：清空整个栈并删服务端会话行。
• 进站在原地 su，不再用 /?return= 跳回原页；带 return= 的地址只打开首页（P4，Gray 11-11 19:47）。
• 身份栈存服务端，最多三层；客户端 token 不带 uid、组或栈。who 显示栈路径（root via styrigx）。
• 时长：
  – styrigx 层 30 天滑动续期，节流：admit 只读，剩余不足一半才续写，每会话每天至多一次；
  – root 层最长 1 小时、前台空闲 15 分钟弹回 styrigx（Page Visibility，页面隐藏或锁屏时暂停计时；实现太重则放宽到 30 分钟）；
  – 救援会话 15 分钟，不续期。

八、用户管理（root）
• useradd <名> [-e YYYY-MM-DD] [-G 组]：生成 16 位以上随机一次性密码，只显示一次，库里只存哈希；Gray 线下发。首登强制改密码，一次性密码 24 小时过期。-e 按 Linux 语义：该日 00:00 Asia/Shanghai 起失效（可用到前一天结束），存 UTC 时间戳。
• userdel <名>：同时清掉该用户的会话、凭据、组；用户行不删，改名为 #deleted-<uid> 并禁用（墓碑），uid 永不复用（免得新用户继承旧 uid 下的头像 / 偏好等数据），名字可再 useradd（P2c #399 实现，割接 PR 记入定稿）。
• usermod -aG|-rG <组> <名>：加组、减组。
• passwd <名>：发一次性密码、首登强制改，其会话全部作废。
• 到期：自动禁用并作废会话，宽限期（30 天）后自动删除，删法同 userdel（同样留墓碑 #deleted-<uid>、禁用，uid 不复用）。
• 站长 styrigx 用 passwd、passkey 改自己的凭据；普通用户（uid 1001 起）只能 passwd 改自己的密码，不能管通行密钥（Gray 11-11 18:10）。passwd 改自己的须先输当前密码，通行密钥自带 WebAuthn 验证。
• whoami 任何人；groups、who 普通用户只看自己，root 看全部。

九、恢复（救援）
• 钥匙放 Cloudflare Secrets Store（每账号只能一个 Store，与其他 Secret 同库）。Gray 在 dashboard 设值、换值，改完运行时即时生效，不用重部署。平时不动，不定期轮换。
• 访客走救援入口，输恢复钥匙，Worker 读 Store 做 constant-time 比对，通过则签 15 分钟一次性 root 会话（类比单用户模式），不续期。
• 指纹：签发成功时在 D1 记该值哈希（不存明文），永久保留；同值再用直接拒绝；指纹写失败则拒绝救援（fail-closed）。复用 P1 的 account_recovery_key 表。
• 白名单：passwd、passkey、whoami、groups、exit、lock。不含换钥匙。按第三节，白名单先于 root 放行检查。
• 救援成功后提示 Gray 去 dashboard 换新值。重置后相关用户 epoch +1。
• 救援入口单独限流（渐进延迟）+ 审计。
• 代码纪律：Worker 运行时绑定只有 get()；代码不出现 Store 写/删调用，合并前 grep 静态检查。部署用的 CF token：Worker 带 Secrets Store 绑定的（account、ai、proxy-rules、space-core、status）其 deploy token 带 Account Secrets Store Edit，这是官方要求（developers.cloudflare.com/secrets-store/access-control：CI 部署带绑定的 Worker 必须 Edit，Read 部署报错；Gray 11-11 17:05 定）；无绑定的（curio-core、daymark-core、space-pages）不带。2026-11-11 17:07 核对 dashboard 与 main 各 wrangler.toml，一一对应。P4 删除 space-core 的全部 SGX_SPACE_* 绑定后，styrigx-space-core-deploy 去掉 Secrets Store 权限（Gray 11-11 17:21 定：收紧），在 space-core 无绑定版本部署变绿之后执行。风险靠运行时只 get() 与 grep 静态检查兜住。
• 全丢：能登 Cloudflare 就设新值。不做破窗。
• 新钥匙 SGX_ACCOUNT_RESCUE_KEY（Gray 05:21 定名，05:23 已在现有 Store 建好，Workers 范围，32 位以上随机值，存 Samsung Pass；每次救援后换值）。P3 只加绑定。两把旧钥匙（SGX_SPACE_RECOVERY_KEY、SGX_ACCOUNT_RECOVERY_KEY）P4 删。

十、安全细节
• 护栏（Muse 05:04，已采纳）：userdel 拒删 root；userdel styrigx（站长）同样拒绝，免得名片无主；usermod 减掉最后一个 wheel / sudoers 成员时警告（减完只能靠救援钥匙）。
• sudo 不能动 root 的凭据（Hark 05:05 评估后采纳）：sudo passwd root、为 root 增删通行密钥一律拒绝，只能在 su root 或救援会话里改。这样 styrigx 凭据被盗时，攻击者仍能 sudo 做破坏，但夺不走 root；Gray 用 root 重置 styrigx 即可收回，不必动用救援钥匙。实现：passwd / passkey 的目标是 root 时，要求当前会话栈顶是 root（su root 或救援），sudo 借权一律拒。root 密码忘了走救援。代价：一条检查 + 一条测试。Muse 05:05 同意。
• 审计扩到 root 的特权内容操作（批量/结构删除、root 改名片等），root 干的事都留痕。
• 认知：styrigx 在 sudoers 里，其凭据经 sudo 可做 root 能做的一切破坏，唯独夺不走 root 凭据（见上条）。真正的边界是 styrigx 凭据，要与 root 同等严防。
• 防枚举：用户不存在与凭据错误返回同一错误、同一耗时路径；不提示某用户有哪些验证方式。
• 限流两维：按 IP 硬上限（6 次/分钟）；按 uid 渐进退避（每个账号一个桶，首次失败后 1s，1s→5s→30s→5min；用户名不存在时按名字记），不硬锁（Gray 11-12 00:17 按 Muse 建议）；通行密钥不计入 uid 冷却。救援（rescue）所有尝试共用 uid:0 一个桶，首次失败后也等 1s（Gray 11-12 00:01 按 Muse 建议）。admit 只读不写，认证失败才写计数。
• 哈希：加盐 + pepper 快速哈希，不用 bcrypt/argon2（Worker 10 ms CPU）。在线防猜靠限流。
• pepper（方案 a）：哈希记 pepper_id，验证按 id 取 pepper，登录成功用账号 pepper 重算。全站只留一把 SGX_ACCOUNT_PASSWORD_PEPPER；旧 SGX_SPACE_PASSWORD_PEPPER（P2 曾绑定到账号 Worker 供迁移，只加绑定，不碰值）P4 连代码、绑定一并删，Secrets Store 里那条按第十二节顺序删（Gray 11-11 17:25「pepper合一把」）。
• epoch：凭据、组、期限任何变更都 bump，严格相等。自己改密码或通行密钥时当前会话续命；root 替别人重置则该用户会话全部作废。
• 会话：D1 不透明 id，HttpOnly、Secure、SameSite Cookie（sgx-session）；网关经 service binding 或读账号 D1 校验，不信客户端 claim。网关不再向下游写 X-Styrigx-Space-* 身份头，子应用一律按 v6 会话判定（P4，Gray 11-11 19:47；删前已 grep 确认奇趣、日刻与其他运行代码不读，Hark 19:40）。
• 无身份访问未列入 ROUTE_ACCESS 的 /api/* 一律 401（原为 404），fail-closed（P4，Gray 11-11 19:47）。
• 错误码：账号接口未登录的 401 码由 account 改为 session；不再使用的错误码删除（P4，Gray 11-11 19:47）。
• admit：一次 D1 查询（会话 + 用户 + 组 + epoch 一次 JOIN）。
• 审计：useradd/userdel/usermod/passwd、su、sudo、救援、登录失败，记 uid、命令、时间、IP 前缀；保留 90 天。
