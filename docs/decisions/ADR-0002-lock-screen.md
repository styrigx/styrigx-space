## 1. 背景

1.1 网站是个人空间，不对公众开放。最初（2026-10-09，2.4.0）锁屏只在前端：访客过 Cloudflare Turnstile 进入，拥有者用通行密钥 / 密码进入；状态记在 sessionStorage，可被 curl 绕过，且新标签页会重复弹锁屏。

1.2 2.4.1（2026-10-10）的服务端方案确立了沿用至今的骨架：
- 服务端签发、Ed25519 签名的会话 cookie，`Domain=.styrigx.com`，HttpOnly、Secure、SameSite=Lax，12 小时；
- 「锁定所有设备」用纪元（epoch）+1 让旧票失效；
- `?return=` 回跳只接受站内路径与 `*.styrigx.com`（防开放重定向）；
- 未进站的页面只返回锁屏，不下发正文；受保护页面 `no-store`；
- 前端 MUST NOT 用 storage / 内存另做判断（分层规范 L0–L6，2026-10-10 定稿，见 SGX-ARCH-001）。

1.3 2.4.1 当时的细节（子站各自的 Pages middleware、公钥分发、`/api/session-epoch` 公开接口 + 60 秒缓存、KV 存纪元）随后全部被取代。

## 3. 现行结论

3.1 进站会话是唯一状态源；四站同源共用一个 cookie（SGX-SPEC-001）。

3.2 进站方式：解锁密码、通行密钥、临时钥匙、分享链接。reauth 只认解锁密码与通行密钥；恢复钥匙只换 reset 票（SGX-SEC-001）。

3.3 网站不提供任何公开的访客入口；需要给别人看时签发临时钥匙或带会话的分享链接。

## 4. 后果

4.1 正面：锁屏无法被绕过；不依赖第三方人机验证；访客权限有明确期限且可随时作废。

4.2 负面 / 代价：
- 切换签名 cookie 名或 pepper 时所有设备回锁屏一次，旧临时钥匙作废（L2 时已发生一次）；
- 分享链接会话最长 7 天，长于密码进站的 12 小时，这是有意为之（由签发者选择档位）。

4.3 遗留：接口路径仍为 `/api/lock-*`（目标态 `/api/space/*` 未实施）；D1 基线里的 `lock_reset_switch` 表与 `core/lock-reset-switch.js` 已无运行时读者，只剩测试引用。

## 5. 从旧任务书保留的工程规则

以下来自 `styrigx-3.0-task.md` 的全局规则仍然有效，已并入 SGX-CON-001：只走 PR、不直推 `main`、不 force push、合并只经 API、每个分支从最新 `main` 开、不删 / 不跳测试、同一问题修两轮仍失败即停下报告。版本号唯一来源 `space/web/data/common/version.yaml`。
