# ADR-0003：账号与进站 V3——门归网站，账号管授权

| 项 | 值 |
|---|---|
| 状态 | 已采纳（已实施）；§2.3 已被 ADR-0006 取代 |
| 日期 | 2026-11-09（#357 合并） |
| 决策者 | Sloan Gray |
| 规范 | SGX-SEC-001 |

## 1. 背景

1.1 早期只有一套「锁屏凭证」，同时承担「能不能进站」与「能不能管理 / 写数据」两件事，并衍生出根凭证、站长凭证、管理凭证等多层交叉（2.11，2026-10-12）。恢复用的钥匙既能重置又能再验证，概念互相顶替。

1.2 账号数据（设备、云同步、头像、授权）与锁屏数据共处一个 Worker、一个库，网关源码里遍布账号鉴权代码。

## 2. 决定

2.1 **两套独立的票据**。进站会话只回答「能不能进来」；账号会话只回答「能不能写 / 看私密」。账号是独立 Worker `styrigx-account`，没有公开路由，只经站点核心的服务绑定进入；站点核心不签、不验账号票，源码里不许出现账号鉴权标识（`check-layers.mjs` 规则 16）。

2.2 **授权由账号回答、网关转交结论**。下游（接口 Worker、AI）只信站点核心交来的结论（RPC `SpaceVerifier.conclusion()` 或 `X-Styrigx-Account-*` 头）；作用域按应用授予，存在 `account_grant`，取消即时生效。

2.3 **〔已被 ADR-0006 取代（v6 身份统一）：三把账号钥匙合成 root 的凭据 + 一把恢复钥匙；`sudo root` → `su root`，`sudo root reauth` 删除，改为 sudo 每次重验；`sudo root reset` → 救援入口〕** **一个概念一个词，一次验证一张票**（账号命名 v2）：`sudo root` 只签 session；`sudo root reauth` 只签 reauth（绑定本机设备）；`sudo root reset` 只用恢复密钥换 reset 票。三把账号钥匙：账号密码、账号通行密钥、恢复密钥；恢复密钥不能登录、不能 reauth。

2.4 **reset 完成后三选一登出**：`all` / `others` / `none`，界面默认 `others`；reset 下的写操作不碰会话。

2.5 **进站侧同构**（进站 v3）：reauth 只认解锁密码 / 通行密钥；恢复钥匙只开 reset；进站凭证、临时钥匙的新建 / 管理 / 作废要 reauth；分享链接新建只要进站会话（链接本身不是明文钥匙），管理要 reauth；立即锁屏只锁当前设备、不验证；所有设备回锁屏要 reauth。

2.6 **会话时长**：进站 12 小时（不续期）；reauth / reset 3 分钟（不续期）；账号会话由 400 天改为 **30 天滑动续期**，剩不到 15 天时重签——常用设备不掉线，闲置 30 天的设备自然过期。

## 4. 后果

4.1 正面：任一侧泄露不影响另一侧；每个敏感操作只有一种合法的验证路径，便于审计与测试。

4.2 代价：换 pepper 后账号密码与解锁密码各需重设一次；改账号钥匙会让其他设备掉线。

4.3 未来（不在本次范围）：开放注册时普通身份用 `user`（与 `admin` / `root` 并列），届时可考虑退役临时钥匙。
