## 0. 说明

- 给 Muse 照着做的逐步清单。设计依据见 ADR-0005；每一步写「做什么 → 应该看到什么」，不符合就记下：步骤编号、设备 / 浏览器、截图或录屏、当时的时间（Asia/Shanghai）。
- 设备：至少一台手机（三星浏览器）+ 一台桌面浏览器（Chrome）。手机上「访客」用无痕标签页最省事。
- 不需要、也不要碰任何 Secret / token 的值；不要打开 Cloudflare 的账单 / 付款页面。
- 身份记号：**访客** = 没进站（`nobody@space:~$`）；**链接会话** = 点带会话的分享链接进来（`nobody@space:~#`）；**已进站** = `sudo styrigx` 通过（`styrigx@space:~#`）；**root** = 再 `sudo root` 登录账号（`root@account:~#`）。

## 9. 代理订阅 sub v3.1

先 `sudo styrigx`，再 `sudo root`。

| # | 做什么 | 应该看到 |
|---|---|---|
| 9.1 | `sub` | 公钥（头尾）、令牌状态、每个来源一行：名字 · 机场域名或 file · 节点数 · on / off / error |
| 9.2 | `sub show`（要 `sudo -v`） | 印出令牌与每个来源的 url，每条带复制按钮 |
| 9.3 | `sub add smoketest`，粘一个可用的机场链接（输入不回显） | 试拉成功才保存；`sub` 里出现 `smoketest` |
| 9.4 | `sub upload smokefile`，选一个本地 YAML | 字符进度条走完；只保留 `proxies:` |
| 9.5 | `sub mv smoketest smoke2` | 改名成功；旧名的 url 立即 404 |
| 9.6 | `sub off smoke2` → `sub on smoke2` | off 时该 url 404；on 后恢复 |
| 9.7 | `sub rm smoke2`、`sub rm smokefile`（各答 y） | 删除成功 |
| 9.8 | `sub key`、`sub token` | **只看提示，不要真的换**（换令牌会让手机里每条 url 失效；换公钥会重新加密全部来源），各自 `^C` 退出 |

### 9.9 CPU 检查（wrangler tail）

1. 在电脑上开：`npx wrangler tail styrigx-proxy-rules --format pretty`（用 Gray 的 Cloudflare 登录；只看日志，不改配置）。
2. 依次做 9.3（`sub add`，同名再 add 一次触发试拉）、9.4（`sub upload`，用最大的那份 YAML）。
3. 等下一次整点 Cron（每 6 小时：0 / 6 / 12 / 18 点 UTC，即北京时间 8 / 14 / 20 / 2 点），看刷新那次。
4. 每次请求 / 定时任务记下日志里的 CPU 时间（`cpuTime` / `CPU Time`）和那个来源的节点数。
5. 判定：免费档每次调用 CPU 上限 10 ms。
   - 都在 10 ms 内 → 通过，`MAX_NODES` 保持 1000（`workers/proxy-rules/src/core/sub/config.js`）。
   - 单源约 1000 节点时超过 10 ms（或日志出现 CPU 超限 / `exceededCpu`）→ 记下数字报给 Gray / Hark，建议把 `MAX_NODES` 降到 500–800（按实测按比例取，留一半余量），另开小 PR 改，不要在线上改。
6. 结束后 `Ctrl C` 关掉 tail。
